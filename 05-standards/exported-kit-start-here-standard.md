# 导出能力包 START-HERE 标准

## 目的

`START-HERE.md` 是所有导出能力包的统一入口文件。

它的职责不是替代 README，而是让使用者或外部 AI 能够快速判断：

- 这个能力包能做什么。
- 什么时候应该调用这个能力包。
- 如何用一句话手动启动。
- 如何配置外部默认读取规则，实现自动触发。
- 执行前应该说明哪些调用信息。

## 适用范围

适用于所有从 WorkflowProject 导出的能力包，例如：

```text
product-manager-kit/
developer-kit/
ui-designer-kit/
tester-kit/
```

## 必须包含的章节

所有导出包的 `START-HERE.md` 必须包含：

```text
# 从这里开始
导出对象
导出时间
这个包能做什么
什么时候使用这个包
一句话启动
更短版本
外部自动读取配置
执行顺序
输出确认格式
使用原则
```

## 标准模板

````md
# 从这里开始

导出对象：{导出对象}
导出时间：{导出时间}

## 这个包能做什么

- {能力 1}
- {能力 2}
- {能力 3}

## 什么时候使用这个包

当用户输入包含以下意图时，优先使用本能力包：

- {触发场景 1}
- {触发场景 2}
- {触发场景 3}

## 一句话启动

```text
请只参考 {kit-name}/ 下的文件工作。请先阅读 {kit-name}/README.md、{kit-name}/usage-guide.md 和 {kit-name}/{主入口 workflow 路径}。我的任务是：{写下你的任务}。请先判断任务类型，再说明会使用哪个 workflow、template 和 scorecard，然后继续产出结果。
```

## 更短版本

```text
请使用 {kit-name} 处理我的任务：{写下你的任务}
```

## 外部自动读取配置

如果希望用户不输入“请使用 {kit-name}”，可以在新项目根目录放置默认读取文件，例如：

```text
AI-WORKFLOW-RULES.md
```

并写入：

```text
你是当前项目的 AI 工作流调度器。

当用户输入任务时，请先判断是否属于 {导出对象} 能力范围。

如果属于，请自动调用 {kit-name}，并先阅读：
1. {kit-name}/START-HERE.md
2. {kit-name}/README.md
3. {kit-name}/usage-guide.md
4. {kit-name}/{主入口 workflow 路径}

执行前请先说明：
- 你判断这是哪一类任务。
- 你将使用哪个 workflow。
- 你将参考哪个 template。
- 你将使用哪个 scorecard 检查结果。

如果不属于本能力包范围，请不要强行调用。
如果无法判断任务类型，请先向用户确认。
```

## 执行顺序

1. 先判断任务类型。
2. 再选择对应 workflow。
3. 再选择对应 template。
4. 产出结果后使用对应 scorecard 检查。
5. 如果信息不足，先列出待确认问题。

## 外部项目输出目录策略

当本能力包在其他项目中使用，并且用户要求把结果保存为文件时，必须先判断当前项目是否已有统一文档目录。

优先级如下：

1. 如果用户明确指定输出目录，使用用户指定目录。
2. 如果项目已有统一文档目录，优先使用该目录，例如 `docs/`、`documents/`、`产品文档/`、`需求文档/`。
3. 如果项目已有明确的领域文档目录，优先使用该目录，例如 `docs/product/`、`docs/prd/`、`product-docs/`。
4. 如果没有任何合适目录，再在项目根目录创建 `docs/`。

不要在外部项目中默认创建或使用 WorkflowProject 内部目录，例如：

```text
04-outputs/
12-projects/
```

如果只是对话中直接输出结果，不需要创建文件。

## 输出确认格式

每次执行前，先输出：

```text
任务判断：{任务类型}
调用能力包：{kit-name}
使用工作流：{workflow}
使用模板：{template}
检查标准：{scorecard}
保存位置：{对话直接输出 / 用户指定目录 / 已有文档目录 / docs/}
```

## 使用原则

- 不确定做什么时，先走总入口。
- 已经明确任务时，直接指定对应工作流。
- 生成结果后，用对应评分表检查。
- 不需要理解原 WorkflowProject。
````

## 质量要求

- 必须能脱离 WorkflowProject 单独理解。
- 必须同时支持手动启动和外部自动读取配置。
- 不写复杂版本号，只记录导出时间。
- 不把一次性项目过程材料写入入口文件。
- 不让使用者必须理解所有细分工作流后才能开始。
- 不把 WorkflowProject 内部输出目录习惯带到外部项目。
