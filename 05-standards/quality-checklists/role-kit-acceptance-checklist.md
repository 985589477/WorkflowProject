# 角色能力包验收清单

## 目的

用于验收一个角色能力包是否已经达到“可以交给外部项目或外部 AI 对话使用”的最低标准。

本清单适用于：

```text
product-manager-kit
developer-kit
ui-designer-kit
tester-kit
```

也适用于后续新增的运营、研究、市场等角色能力包。

## 使用方式

在角色包导出、升级或复盘时使用本清单。

如果任一关键项不满足，不应宣称该角色包已经完成，只能标记为：

```text
可试用 / 待补齐 / 需要真实案例验证
```

## 验收清单

| 类别 | 检查项 | 是否通过 | 说明 |
| --- | --- | --- | --- |
| 角色边界 | 是否说明该角色能做什么、不能做什么 |  |  |
| 角色边界 | 是否说明典型输入和典型输出 |  |  |
| 总入口 | 是否有 `START-HERE.md` |  |  |
| 总入口 | 是否有主入口工作流 |  |  |
| 总入口 | 主入口是否是生命周期编排器，而不是单点分流器 |  |  |
| 生命周期 | 是否定义从输入到产出、检查、交接、复盘的完整链路 |  |  |
| 生命周期 | 是否说明哪些阶段可以跳过，以及跳过原因 |  |  |
| 主动询问 | 信息不足时是否要求主动询问用户 |  |  |
| 主动询问 | 是否避免把 AI 推断写成事实 |  |  |
| 阶段门禁 | 进入关键产出前是否有质量门禁 |  |  |
| 阶段门禁 | 进入跨角色交接前是否确认边界和验收标准 |  |  |
| 任务拆解 | 执行型任务是否要求先拆解再逐条执行 |  |  |
| 输出格式 | 是否有稳定的模板 |  |  |
| 输出格式 | 是否有评分表或质量检查方式 |  |  |
| 外部使用 | 是否有 `README.md`、`usage-guide.md`、`INSTALL.md` |  |  |
| 外部使用 | 是否有快速启动示例 |  |  |
| 外部使用 | 是否说明 Codex 和 Cursor 如何使用 |  |  |
| 输出目录 | 是否避免在外部项目中默认创建 `{目标文档目录}/` 或 `12-projects/` |  |  |
| 记忆管理 | 是否说明长期迭代时如何维护项目记忆摘要 |  |  |
| 可发现性 | 是否能在 `12-projects/asset-index.md` 中找到 |  |  |
| 可验证性 | 是否至少经过一次真实或模拟任务验证 |  |  |

## 判定标准

| 结果 | 标准 |
| --- | --- |
| 通过 | 关键项全部满足，并至少有一次真实或模拟验证 |
| 可试用 | 主入口、模板、评分表、使用说明齐全，但真实案例不足 |
| 待补齐 | 缺少主入口、模板、评分表、使用说明中的任一关键项 |
| 不通过 | 角色边界不清，或外部项目无法独立使用 |

## 最低交付物

一个可试用角色包至少包含：

```text
START-HERE.md
README.md
usage-guide.md
INSTALL.md
manifest.md
workflows/{role}/{role}-workflow.md
templates/{role}/{main-template}.md
scorecards/{role}-scorecard.md
examples/quick-start-example.md
integrations/codex-usage.md
integrations/cursor-usage.md
```
