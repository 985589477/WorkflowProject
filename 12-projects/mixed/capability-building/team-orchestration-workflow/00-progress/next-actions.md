# 下一步判断

## 使用说明

这里用于帮助用户判断项目下一步该往哪里走。

## 当前项目状态

completed，跨角色团队总调度能力已建设完成，并已补充 Skill 与真实子 Agent 的复杂度分流、任务简报、结果回报和运行能力门禁。

## 可选方向

### 方向 A：用真实完整需求验证

- 价值：验证产品、UI、开发、测试是否能按优先级接管、交接、互相验收。
- 风险：真实需求过大时，输出可能较长。
- 建议：优先选择一个中等复杂度功能，从产品需求开始跑完整链路。

### 方向 B：拆分跨角色验收工作流

- 价值：如果后续经常出现“开发交付后谁来验收”的问题，可以单独沉淀三方验收规则。
- 风险：未经过真实案例前拆分，可能过早抽象。
- 建议：等真实 badcase 出现后再拆。

### 方向 C：导出 team-kit

- 价值：可以在外部项目里独立使用团队总调度。
- 风险：当前还没有真实案例验证，导出后可能还要返工。
- 建议：先验证，再导出。

### 方向 D：验证父 Agent 与子 Agent 分流

- 价值：确认简单任务不会被过度拆分，组合任务不会被单 Agent 冒充完成。
- 建议：在支持子 Agent 的运行环境中验证一个完整功能，并分别验证一个简单单角色任务。

## 推荐下一步

使用一个真实完整需求验证 `04-workflows/mixed/team-orchestration-workflow.md`，重点观察：

- 是否能正确判断当前接管角色。
- 是否能按产品 -> UI -> 开发 -> 测试推进。
- 是否能发现上游产物让下游看不懂的问题。
- 是否能判断开发交付是否通过产品、UI、测试验收。
- 是否能把沟通问题记录成 badcase，并指向对应角色能力项目优化。

## 待确认问题

- 是否现在就拿一个真实需求验证。
- 是否需要后续导出独立 `team-kit`。
- 组合任务运行环境是否真实提供子 Agent 工具。
