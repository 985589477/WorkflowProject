## 沉淀价值

单角色能力解决“某个角色怎么做事”，团队总调度解决“多个角色如何协作”。

这个能力后续可以作为完整项目的入口，让用户只需要提出需求，由总调度判断：

- 是否先由产品经理澄清需求。
- 是否需要 UI 设计师补设计交接。
- 是否可以进入开发。
- 是否需要测试先检查验收标准。
- 哪个角色发现了上游输出问题。

## 后续沉淀建议

真实案例验证后，再判断是否继续拆分：

- 跨角色验收工作流。
- badcase 复盘工作流。
- team-kit 导出包。

## 本次增强结论

团队总调度不是“所有任务都创建子 Agent”。它先做复杂度分流：简单任务保持单 Agent + Skill 的低成本路径；组合任务才使用父 Agent + 子 Agent 的隔离上下文和协作路径。运行环境不支持真实子 Agent 时必须显式降级，不能把单 Agent 顺序执行包装成子 Agent 协作。
