# 决策记录

## 使用说明

这里记录项目执行过程中重要决策的原因。

进度记录回答“做到了哪一步”，决策记录回答“为什么这么做”。

## 记录模板

```md
## 决策：{决策标题}

### 背景

为什么出现这个问题？

### 决策

最终决定做什么？

### 原因

为什么这样做？

### 影响

这个决策会影响哪些文件、流程或后续方向？

### 日期

YYYY-MM-DD
```
# 决策记录

## 2026-10-13：将“代码评审”独立为 developer-kit 工作流

### 背景

实现、测试和文档同步之后，仍然需要一个交付前质量闸门，用来发现问题而不是只总结成果。

### 决策

将“代码评审”作为第二阶段最后一个工作流。

### 原因

- 评审应覆盖代码、测试、文档、风险和可维护性。
- 评审输出应问题优先，便于用户判断是否能交付。
- 评审发现的问题可以进入 AI 协作复盘，反哺后续规则。

### 影响

developer-kit 第二阶段能力链路完成：

```text
代码实现执行 -> 测试与验收 -> 文档同步 -> 代码评审
```
