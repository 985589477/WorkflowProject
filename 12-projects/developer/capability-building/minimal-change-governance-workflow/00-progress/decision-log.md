# 决策记录

## 2026-10-14：以子角色方式融合 Ponytail

决策：将 Ponytail 的核心原则融合为开发角色中的“最小必要变更守门人”，而不是作为独立外部依赖或替换 developer-kit。

原因：

- 当前 developer-kit 已经覆盖项目理解、模块边界、风险、实现、测试、评审和发布等完整链路。
- Ponytail 更适合作为实现前和评审时的约束能力。
- 直接照搬会削弱当前开发治理体系的完整性。

## 2026-10-14：不为了少写代码牺牲必要质量

决策：“少写代码”不能用于省略安全校验、权限校验、错误处理、可访问性和测试。

原因：

- developer-kit 面向真实项目治理，不能只追求代码量最少。
- 最小必要变更应是“最小完整变更”，不是“不完整变更”。
