# 输入分析

## 核心问题

项目长期维护中，架构失控常常不是因为没人做决策，而是因为：

- 决策原因没有记录。
- 备选方案和放弃原因消失在聊天记录里。
- 后续 AI 只看到代码，不知道历史约束。
- 临时方案变成永久方案。
- 新人不知道什么时候可以推翻旧设计。

因此，需要 ADR 工作流记录重要决策的上下文和取舍。

## 与前后工作流的关系

| 阶段 | 工作流 | 关系 |
| --- | --- | --- |
| 前置 | `requirement-to-architecture-workflow.md` | 发现架构影响和决策点。 |
| 前置 | `module-boundary-analysis-workflow.md` | 提供模块边界取舍。 |
| 前置 | `code-review-workflow.md` | 发现需要记录的设计问题。 |
| 当前 | `architecture-decision-record-workflow.md` | 记录长期架构决策。 |
| 后续 | `documentation-sync-workflow.md` | 将 ADR 入口同步到相关文档。 |

## 必须覆盖的能力

1. ADR 必要性判断。
2. 决策背景。
3. 备选方案。
4. 选择理由。
5. 放弃原因。
6. 影响范围。
7. 风险代价。
8. 状态追踪。
9. 复盘条件。

## 设计结论

本工作流应输出 ADR 文档。

它要回答：

```text
为什么做这个架构选择？
当时还考虑过什么？
这个选择带来什么影响？
未来什么时候应该重新看它？
```
