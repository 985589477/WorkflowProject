# 输入分析

## 核心问题

发布环节常见失控点是：

- 只确认代码能构建，却没确认能上线。
- 没有发布前检查清单。
- 没有明确回滚触发条件。
- 回滚后不知道如何验证恢复。
- 上线后没有观察窗口和指标。
- 发布失败没有进入复盘。

因此，本能力要把发布变成可检查、可执行、可回退、可观察的流程。

## 与前后工作流的关系

| 阶段 | 工作流 | 关系 |
| --- | --- | --- |
| 前置 | `change-risk-assessment-workflow.md` | 发布风险分级。 |
| 前置 | `environment-config-governance-workflow.md` | 发布配置和环境差异确认。 |
| 前置 | `testing-verification-workflow.md` | 提供测试与验收结果。 |
| 前置 | `code-review-workflow.md` | 提供交付前评审结果。 |
| 当前 | `release-and-rollback-workflow.md` | 管理发布、回滚和上线观察。 |
| 后续 | `ai-collaboration-retrospective-workflow.md` | 发布问题进入复盘沉淀。 |

## 必须覆盖的能力

1. 发布范围。
2. 发布前检查。
3. 发布步骤。
4. 回滚方案。
5. 降级或止损方案。
6. 上线后观察。
7. 阻塞问题。
8. 发布判断。
9. 复盘入口。

## 设计结论

本工作流应输出“发布与回滚治理报告”。

它要回答：

```text
现在能不能发？
怎么发？
失败怎么退？
上线后看什么？
出问题怎么复盘？
```
