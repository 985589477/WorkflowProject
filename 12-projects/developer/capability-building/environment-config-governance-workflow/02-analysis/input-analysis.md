# 输入分析

## 核心问题

项目环境和配置失控常见表现为：

- 环境变量没人知道用途。
- 本地能跑，测试或生产跑不起来。
- `.env.example` 过期。
- 启动命令、构建命令、部署说明不一致。
- 真实密钥被写入仓库。
- AI 修改配置但没有说明影响环境。

因此，本能力要让配置变更可理解、可验证、可回滚。

## 与前后工作流的关系

| 阶段 | 工作流 | 关系 |
| --- | --- | --- |
| 前置 | `change-risk-assessment-workflow.md` | 配置变更需要风险分级。 |
| 前置 | `dependency-and-tech-debt-workflow.md` | 外部服务或依赖配置可能带来技术债。 |
| 当前 | `environment-config-governance-workflow.md` | 管理环境变量、启动、构建和部署配置。 |
| 后续 | `testing-verification-workflow.md` | 验证启动、构建、测试和连接。 |
| 后续 | `documentation-sync-workflow.md` | 同步配置说明和示例。 |
| 后续 | `release-and-rollback-workflow.md` | 涉及部署时进入发布回滚治理。 |

## 必须覆盖的能力

1. 配置对象识别。
2. 现有配置摘要。
3. 配置项清单。
4. 环境差异。
5. 配置变更分析。
6. 风险清单。
7. 治理方案。
8. 验证要求。
9. 回滚要求。
10. 文档同步建议。

## 设计结论

本工作流应输出“环境与配置治理报告”。

它要回答：

```text
这个配置是什么？
用在哪些环境？
缺失或错误会怎样？
怎么验证？
失败后如何回滚？
文档要不要同步？
```
