# 输入分析

## 核心问题

代码实现完成后，常见问题是：

- 只说“已完成”，没有验证证据。
- 只运行构建，没有覆盖实际业务路径。
- 测试失败但没有解释。
- 无法验证但没有说明。
- 没有手动验收步骤，用户不知道怎么检查。
- 没有回归范围，容易漏掉旧功能。

因此，本能力要把验证从一句话变成结构化证据。

## 与前后工作流的关系

| 阶段 | 工作流 | 关系 |
| --- | --- | --- |
| 前置 | `implementation-workflow.md` | 提供修改文件和实现交付说明。 |
| 前置 | `impact-analysis-workflow.md` | 提供测试影响和回归范围。 |
| 当前 | `testing-verification-workflow.md` | 执行验证并输出测试与验收报告。 |
| 后续 | `documentation-sync-workflow.md` | 同步验证结果和使用说明到文档。 |
| 后续 | `code-review-workflow.md` | 评审实现与验证质量。 |

## 必须覆盖的能力

1. 验证目标。
2. 验证计划。
3. 自动验证。
4. 手动验收。
5. 回归范围。
6. 失败处理。
7. 未验证内容。
8. 交付判断。

## 设计结论

本工作流应输出“测试与验收报告”。

它要回答：

```text
本次变更被验证了吗？
验证覆盖了哪些地方？
哪些地方没验证？
现在是否适合交付？
```
