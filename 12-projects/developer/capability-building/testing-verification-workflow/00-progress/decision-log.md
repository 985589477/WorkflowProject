# 决策记录

## 使用说明

这里记录项目执行过程中重要决策的原因。

进度记录回答“做到了哪一步”，决策记录回答“为什么这么做”。

## 记录模板

```md
## 决策：{决策标题}

### 背景

为什么出现这个问题？

### 决策

最终决定做什么？

### 原因

为什么这样做？

### 影响

这个决策会影响哪些文件、流程或后续方向？

### 日期

YYYY-MM-DD
```
# 决策记录

## 2026-10-13：将“测试与验收”独立为 developer-kit 工作流

### 背景

代码实现后，如果没有验证证据和验收说明，用户很难判断是否真的可以交付。

### 决策

将“测试与验收”作为实现执行之后的独立工作流。

### 原因

- 验证需要根据风险和影响范围制定。
- 自动测试、构建、手动验收和回归检查需要统一记录。
- 未验证内容和失败结果必须显式说明。

### 影响

developer-kit 第二阶段能力链路变为：

```text
代码实现执行 -> 测试与验收 -> 文档同步 -> 代码评审
```
