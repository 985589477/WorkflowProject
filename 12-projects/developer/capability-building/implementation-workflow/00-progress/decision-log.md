# 决策记录

## 使用说明

这里记录项目执行过程中重要决策的原因。

进度记录回答“做到了哪一步”，决策记录回答“为什么这么做”。

## 记录模板

```md
## 决策：{决策标题}

### 背景

为什么出现这个问题？

### 决策

最终决定做什么？

### 原因

为什么这样做？

### 影响

这个决策会影响哪些文件、流程或后续方向？

### 日期

YYYY-MM-DD
```
# 决策记录

## 2026-10-13：将“代码实现执行”独立为 developer-kit 工作流

### 背景

第一阶段已经完成开发前治理，但还需要规定 AI 真正改代码时的执行方式。

### 决策

将“代码实现执行”作为第二阶段第一个工作流。

### 原因

- AI 写代码时需要保护用户已有改动。
- 实现必须受影响范围和风险等级约束。
- 交付必须包含验证结果、未验证内容和剩余风险。

### 影响

developer-kit 第二阶段能力链路开始：

```text
影响范围分析 -> 代码实现执行 -> 测试验证 -> 文档同步 -> 代码评审
```
