# 决策记录

## 使用说明

这里记录项目执行过程中重要决策的原因。

进度记录回答“做到了哪一步”，决策记录回答“为什么这么做”。

## 记录模板

```md
## 决策：{决策标题}

### 背景

为什么出现这个问题？

### 决策

最终决定做什么？

### 原因

为什么这样做？

### 影响

这个决策会影响哪些文件、流程或后续方向？

### 日期

YYYY-MM-DD
```
# 决策记录

## 2026-10-13：将“影响范围分析”独立为 developer-kit 工作流

### 背景

用户希望 AI 在进入实现前，不只是知道风险等级，还要清楚具体会影响哪些文件、接口、数据、测试和文档。

### 决策

将“影响范围分析”作为变更风险评估之后、代码实现之前的独立工作流。

### 原因

- 风险评估回答能不能做，影响范围分析回答具体动哪里。
- 实现前需要明确确定影响、可能影响、无需修改和待确认区域。
- 测试和文档影响必须提前进入开发计划。

### 影响

developer-kit 第一阶段能力链路完成：

```text
新项目启动治理 -> 已有项目理解 -> 需求到架构影响分析 -> 模块边界分析 -> 变更风险评估 -> 影响范围分析
```
