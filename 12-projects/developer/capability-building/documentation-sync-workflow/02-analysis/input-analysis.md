# 输入分析

## 核心问题

项目长期失控的常见原因之一是文档和代码脱节：

- README 里的启动命令过期。
- AGENTS 里的 AI 协作规则不再适用。
- API 文档和真实接口不一致。
- 架构文档没有反映模块边界变化。
- 测试和验收结果没有记录。
- 后续 AI 读取旧文档后做出错误判断。

因此，本能力应把文档同步变成开发闭环的一部分。

## 与前后工作流的关系

| 阶段 | 工作流 | 关系 |
| --- | --- | --- |
| 前置 | `implementation-workflow.md` | 提供实现变更事实。 |
| 前置 | `testing-verification-workflow.md` | 提供验证结果和未验证内容。 |
| 当前 | `documentation-sync-workflow.md` | 判断并同步项目文档。 |
| 后续 | `code-review-workflow.md` | 检查代码、测试和文档是否一致。 |

## 必须覆盖的能力

1. 变更事实提取。
2. 文档影响判断。
3. 同步策略选择。
4. 文档更新。
5. 一致性检查。
6. 未同步原因记录。
7. 待确认内容。
8. 后续建议。

## 设计结论

本工作流应输出“文档同步报告”。

它要回答：

```text
这次代码变更是否让项目文档失真？
哪些文档需要更新？
哪些不用更新？
哪些无法确认？
更新后是否与真实项目一致？
```
