# 决策记录

## 使用说明

这里记录项目执行过程中重要决策的原因。

进度记录回答“做到了哪一步”，决策记录回答“为什么这么做”。

## 记录模板

```md
## 决策：{决策标题}

### 背景

为什么出现这个问题？

### 决策

最终决定做什么？

### 原因

为什么这样做？

### 影响

这个决策会影响哪些文件、流程或后续方向？

### 日期

YYYY-MM-DD
```
# 决策记录

## 2026-10-13：将“文档同步”独立为 developer-kit 工作流

### 背景

代码实现和测试完成后，如果文档不更新，后续用户和 AI 会读取过期信息，导致误判项目结构、命令、接口或模块边界。

### 决策

将“文档同步”作为测试与验收之后、代码评审之前的独立工作流。

### 原因

- 文档同步需要基于真实变更事实。
- 不同文档类型需要不同同步策略。
- 文档一致性会影响后续 AI 协作质量。

### 影响

developer-kit 第二阶段能力链路变为：

```text
代码实现执行 -> 测试与验收 -> 文档同步 -> 代码评审
```
