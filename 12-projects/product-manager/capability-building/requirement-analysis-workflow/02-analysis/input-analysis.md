# 输入分析

## 资料来源

来自产品经理能力体系项目的推荐下一步。

## 任务背景

产品经理能力体系已经规划完成，第一阶段推荐优先建设：

1. 需求分析。
2. PRD 生成。
3. 验收标准。

其中需求分析是上游能力，决定后续 PRD、功能规划和验收标准是否准确。

## 核心任务

生成一份产品经理需求分析工作流。

## 任务目标

1. 定义需求分析工作流的目的、适用场景、输入要求、执行步骤、输出结果和质量检查。
2. 明确需求分析如何处理模糊想法、已有材料、会议纪要、用户反馈等输入。
3. 明确需求分析输出应该保存到项目目录哪里。
4. 为后续 PRD 工作流提供上游输入。
5. 判断是否沉淀到全局产品经理工作流目录。

## 关键事实

- `product-manager-workflow.md` 是产品经理总入口。
- `requirement-analysis-workflow.md` 应作为产品经理细分能力 workflow。
- 需求分析不直接替代 PRD。
- 需求分析的核心是明确问题、用户、场景、目标、边界、事实、推断和待确认信息。

## 限制条件

- 不应生成 PRD 完整内容。
- 不应把需求分析写成泛泛原则。
- 每个步骤要有输入、动作和产出。
- 输出要能继续支撑 PRD、功能规划和验收标准。

## 不确定信息

- 是否同步生成需求分析模板。
- 是否同步生成评分表。
- 是否需要针对 AI 产品经理场景增强。

## 判断

本项目先输出需求分析 workflow，并沉淀到：

```text
04-workflows/product-manager/requirement-analysis-workflow.md
```

模板和评分表暂不一次性生成，后续可以通过独立项目继续建设。
