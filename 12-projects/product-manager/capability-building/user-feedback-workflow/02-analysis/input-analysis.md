# 输入分析

## 输入是否充足

输入充足。

当前已有典型反馈样例，且这些反馈已经在项目中转化出了项目索引、dashboard、启动话术和能力建设链路，因此可以抽象出用户反馈整理工作流。

## 用户反馈整理要解决的问题

用户反馈通常是零散、情绪化、重复和不完整的。

如果不整理，容易出现：

- 把吐槽直接当需求。
- 忽略高频问题。
- 看不到反馈背后的真实痛点。
- 无法判断是否值得进入需求分析。
- 无法把反馈沉淀为需求机会。

## 设计原则

1. 保留用户原话，不直接改写成结论。
2. 区分反馈、问题、痛点、需求机会和 AI 推断。
3. 识别高频问题和强烈情绪。
4. 标记反馈来源和可信度。
5. 不把单条反馈直接升级成确定需求。
6. 判断是否建议进入需求分析。

## 输出结构建议

用户反馈整理应至少包含：

- 原始反馈摘要。
- 反馈分类。
- 用户问题。
- 用户痛点。
- 需求机会。
- 高频程度。
- 优先级线索。
- 待确认问题。
- 是否建议进入需求分析。
