# 输入分析

## 任务类型

这是产品经理能力建设项目，不是真实版本复盘项目。

本项目要建设的是一套可复用方法，让后续真实项目可以稳定复盘版本结果和过程问题。

## 能力定位

版本复盘位于产品经理闭环改进能力层。

它主要回答：

- 原计划是什么。
- 实际完成了什么。
- 目标是否达成。
- 哪些需求、范围或优先级发生了变化。
- 问题原因是什么。
- 哪些经验可以沉淀。
- 下一轮产品工作应该怎么调整。

## 与已有能力的关系

| 能力 | 关系 |
| --- | --- |
| 版本规划 | 复盘时对比原版本目标和范围 |
| 产品路线图 | 判断版本结果是否影响长期路线 |
| 需求变更评估 | 复盘变更发生原因和影响 |
| 用户反馈整理 | 复盘上线后的用户反馈 |
| 验收标准 | 判断交付是否达成完成标准 |
| 需求池管理 | 将复盘后的遗留问题和新需求回流需求池 |

## 输出边界

版本复盘不直接重写 PRD，不直接做绩效评价，也不把所有问题归因到个人。

它应该输出：

- 版本背景和目标。
- 原计划与实际结果对比。
- 目标达成情况。
- 需求交付情况。
- 变更影响。
- 质量和协作问题。
- 原因分析。
- 经验沉淀。
- 后续行动。

## 质量重点

- 必须区分事实、判断和建议。
- 不能只写空泛总结。
- 必须有原计划和实际结果对比。
- 必须明确问题原因和后续动作。
- 必须把可继续推进的事项回流需求池、路线图或下一版本规划。
