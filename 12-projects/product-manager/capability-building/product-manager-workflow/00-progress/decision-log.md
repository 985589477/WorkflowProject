# 决策记录

## 使用说明

这里记录项目执行过程中重要决策的原因。

进度记录回答“做到了哪一步”，决策记录回答“为什么这么做”。

## 记录模板

```md
## 决策：{决策标题}

### 背景

为什么出现这个问题？

### 决策

最终决定做什么？

### 原因

为什么这样做？

### 影响

这个决策会影响哪些文件、流程或后续方向？

### 日期

YYYY-MM-DD
```

## 决策：新建独立项目重跑链路

### 背景

用户希望通过 `idea-to-input-generator` 重新做一遍产品经理工作流。

### 决策

新建项目：

```text
12-projects/product-manager/capability-building/product-manager-workflow/
```

### 原因

这样可以保留上一版项目记录，同时清楚验证新增的“想法转输入”能力。

### 影响

本项目成为第二次验证项目，重点不只是产出 workflow，而是验证从模糊想法到标准 input 的入口链路。

### 日期

2026-10-12

## 决策：用 v2 覆盖全局产品经理工作流

### 背景

v2 输出补上了上一版缺少的“想法转输入”前置步骤。

### 决策

用本项目输出更新：

```text
04-workflows/product-manager/product-manager-workflow.md
```

### 原因

v2 更符合用户真实使用方式，能降低 input 准备成本。

### 影响

后续产品经理项目默认从“模糊想法或已有材料”两种入口开始，而不是只假设用户已有材料。

### 日期

2026-10-12
