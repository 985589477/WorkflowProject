# 输入分析

## 资料来源

本次输入由 `06-templates/meta/idea-to-input-generator.md` 根据用户一句话描述整理而来。

用户原始描述：

```text
我想要通过刚刚的idea-to-input-generator重新做一遍product-mamager-workflow
```

## 任务背景

上一版产品经理工作流已经完成，但它是在 AI 较多主动整理的基础上生成的。用户随后意识到：如果后续每次真实项目都要用户先准备完整 input，使用成本仍然很高。

因此，本次任务要验证：

```text
模糊想法是否可以稳定转成标准 input，再进入后续项目链路。
```

## 核心任务

重新生成一版产品经理通用工作流，并把“想法转输入”作为正式前置步骤纳入产品经理工作流。

## 任务目标

1. 验证 `idea-to-input-generator` 是否能支撑真实项目启动。
2. 生成一份新版产品经理工作流。
3. 对比上一版，确认新版是否更适合真实用户使用。
4. 判断是否更新全局产品经理工作流。

## 关键事实

- 用户只有一句模糊描述，仍然可以生成标准 input。
- 标准 input 中已经保留用户原话、背景、目标、事实、推断和待确认信息。
- 上一版产品经理工作流已经存在。
- 新版应解决上一版对“input 生成成本”覆盖不足的问题。

## 限制条件

- 不能把 AI 推断写成用户确认事实。
- 不能覆盖上一版项目记录。
- 不能只生成抽象原则，必须能指导后续真实产品项目。
- 如果要更新全局工作流，需要说明更新理由。

## 不确定信息

- 用户是否希望立即覆盖全局工作流。
- 用户是否希望本项目也进入案例库。
- 新版工作流是否需要配套产品经理模板。

## 判断

本次应生成“产品经理通用工作流 v2”，重点改进：

- 增加“第 0 步：想法转输入”。
- 明确标准 input 的作用。
- 明确什么时候需要澄清问题，什么时候可以继续执行。
- 将产品经理任务从“有材料才开始”改为“有想法也能开始”。
