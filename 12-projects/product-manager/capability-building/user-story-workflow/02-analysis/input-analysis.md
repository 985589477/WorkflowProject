# 输入分析

## 输入是否充足

输入充足。

当前已有目标用户、用户场景、功能清单、PRD 和功能说明，足以抽象出用户故事生成工作流。

## 用户故事能力要解决的问题

PRD 和功能规划偏产品结构，用户故事则把功能转回用户视角，帮助后续设计、开发和测试理解功能背后的用户目标。

如果缺少用户故事，容易出现：

- 功能只有名称，没有用户动机。
- 开发只知道做什么，不知道为什么做。
- 测试只验证功能存在，不验证用户目标是否达成。
- UI 设计缺少场景和用户动作。

## 设计原则

1. 用户故事必须包含角色、目标和价值。
2. 用户故事必须能追溯到用户场景、功能或产品目标。
3. 不把系统任务伪装成用户故事。
4. 不写没有用户价值的空泛故事。
5. 每条用户故事应能继续生成验收条件。
6. 对不明确的用户角色或目标写入待确认问题。

## 输出结构建议

用户故事应至少包含：

- 用户角色。
- 用户目标。
- 用户价值。
- 对应功能。
- 优先级。
- 来源。
- 验收提示。
