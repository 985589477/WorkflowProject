# 输入分析

## 输入是否充足

输入充足。

当前能力建设目标明确：需要抽象优先级判断流程，而不是为某个具体产品直接排序。

## 优先级判断要解决的问题

产品经理常面对多个需求、功能或机会，如果没有稳定判断框架，容易出现：

- 谁声音大就先做谁。
- 把紧急当重要。
- 只看用户价值，不看成本和风险。
- 只看业务目标，忽略用户痛点。
- 当前版本和后续版本边界混乱。

## 设计原则

1. 先明确判断目标。
2. 优先级必须有判断依据。
3. 同时考虑用户价值、业务价值、紧急程度、成本、风险和依赖。
4. 区分 P0、P1、P2 和暂不做。
5. 不把信息不足的事项强行排序。
6. 保留待确认问题。

## 输出结构建议

优先级判断应至少包含：

- 判断目标。
- 候选项列表。
- 判断维度。
- 分项评分或判断说明。
- 优先级结果。
- 暂不做说明。
- 风险和待确认问题。
- 后续建议。
