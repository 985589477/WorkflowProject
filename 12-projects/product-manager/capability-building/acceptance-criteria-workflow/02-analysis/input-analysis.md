# 输入分析

## 输入是否充足

输入充足。

当前已有 PRD 初稿、功能说明、验收标准样例和 PRD 评审结果，足以抽象出验收标准生成工作流。

## 验收标准能力要解决的问题

PRD 和功能说明描述“要做什么”，但开发和测试还需要知道“做到什么程度算完成”。

如果缺少验收标准，容易出现：

- 产品认为完成，开发认为还有边界没定义。
- 测试无法判断功能是否通过。
- AI 输出的 PRD 停留在描述层，无法进入执行。
- 异常状态、空状态和边界条件被遗漏。

## 设计原则

1. 每条验收标准必须对应功能或用户场景。
2. 验收标准必须可观察、可验证。
3. 区分正常流程、异常流程、空状态和边界情况。
4. 不把实现方案写成验收标准。
5. 不把主观感受写成验收标准。
6. 保留待确认问题。

## 输出结构建议

验收标准应至少包含：

- 功能模块。
- 验收项。
- 前置条件。
- 操作步骤。
- 预期结果。
- 异常或边界情况。
- 优先级。
- 来源。
