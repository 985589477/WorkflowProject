# 输入分析

## 资料来源

来自用户对产品经理体系建设的进一步需求。

## 任务背景

当前已经有产品经理通用工作流，但它更像一个总入口。随着后续项目增多，仅靠一个总工作流无法支撑产品经理角色的长期建设。

因此，本项目需要从“单个 workflow”升级为“产品经理能力体系规划”。

## 核心任务

规划产品经理角色的能力细分体系，并输出后续建设路线。

## 任务目标

1. 定义产品经理能力体系的分层。
2. 明确每个能力模块的职责。
3. 明确每个能力模块未来需要哪些工作流、模板、案例和评估标准。
4. 形成优先级路线图。
5. 给出下一批可创建的真实项目。

## 关键事实

- 已有 `product-manager-workflow.md` 作为产品经理总入口。
- 用户希望建立体系，而不是一次性生成大量文档。
- 当前项目框架支持从项目产物沉淀到全局目录。
- 产品经理体系应与 `02-roles/`、`04-workflows/`、`06-templates/`、`09-examples/`、`11-evaluations/` 产生映射关系。

## 限制条件

- 不应一次性补齐所有细分 workflow。
- 不应把产品经理体系写成抽象能力口号。
- 需要给出可执行的后续项目拆分。
- 需要说明每个能力沉淀到哪里。

## 不确定信息

- 产品经理定位是否偏通用。
- 是否优先围绕 AI 协作场景。
- 是否需要先建设 PRD 能力，还是先建设需求分析能力。

## 判断

本项目应输出“产品经理能力体系地图”，而不是“产品经理能力说明文”。

能力体系应至少包含：

- 能力模块。
- 典型任务。
- 输入类型。
- 输出产物。
- 需要建设的 workflow。
- 需要建设的 template。
- 评估标准。
- 优先级。
- 后续项目建议。

## 推荐产出

```text
04-outputs/product-manager-capability-system.md
```

如果评审通过，可沉淀到：

```text
10-knowledge-base/patterns/product-manager-capability-system.md
```

并同步更新：

```text
02-roles/product-manager/role-definition.md
04-workflows/product-manager/README.md
```
