# 沉淀记录

## 沉淀结论

需求变更评估工作流可以沉淀为产品经理全局能力。

## 已沉淀文件

```text
04-workflows/product-manager/requirement-change-evaluation-workflow.md
06-templates/product-manager/requirement-change-evaluation-template.md
11-evaluations/output-scorecards/requirement-change-evaluation-scorecard.md
```

## 沉淀原因

- 真实产品执行过程中经常出现新增需求、范围变化和优先级调整。
- 没有变更评估机制时，容易导致范围失控、延期、返工或团队认知不一致。
- 该工作流可以和 PRD、验收标准、版本规划、产品路线图、需求池形成联动。

## 使用建议

当项目已经进入 PRD、设计、开发、测试或上线准备阶段，又出现新增需求或范围调整时，使用需求变更评估工作流。

当变更只是一个尚未确定的新想法时，优先进入需求池或需求分析。

## 后续建议

下一项建议建设：

```text
版本复盘工作流
```

原因：需求变更会影响版本执行，版本完成后需要复盘目标达成、变更影响、问题原因和后续改进。
