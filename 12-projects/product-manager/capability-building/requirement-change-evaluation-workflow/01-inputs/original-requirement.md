# 原始需求

## 用户想法

继续完成产品经理能力建设，下一项建设需求变更评估工作流。

## 背景

当前产品经理能力体系已经具备需求池、产品路线图、版本规划、优先级判断、PRD 和验收标准等能力。

真实项目执行过程中，经常会出现：

- 新需求临时插入。
- 已定需求范围变化。
- 优先级突然调整。
- 版本中途增加或删除功能。
- 设计、开发、测试已经启动后，业务方要求修改。

如果没有变更评估机制，产品经理容易只凭感觉决定是否接受变更，导致范围失控、延期、返工或团队认知不一致。

## 目标

生成一个可复用的需求变更评估工作流，并沉淀为全局能力文件。
