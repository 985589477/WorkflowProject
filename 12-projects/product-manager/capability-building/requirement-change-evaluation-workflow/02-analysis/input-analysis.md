# 输入分析

## 任务类型

这是产品经理能力建设项目，不是真实需求变更处理项目。

本项目要建设的是一套可复用方法，让后续真实项目可以稳定评估需求变更影响。

## 能力定位

需求变更评估位于产品经理执行管控能力层。

它主要回答：

- 变更是什么。
- 为什么现在提出变更。
- 变更影响哪些范围。
- 是否影响目标、版本、PRD、设计、开发、测试或上线。
- 是否应该接受、暂缓、拒绝或进入下一版本。
- 需要谁确认。

## 与已有能力的关系

| 能力 | 关系 |
| --- | --- |
| 需求池管理 | 变更请求可进入需求池并保留状态 |
| 优先级判断 | 判断变更是否高于当前事项 |
| 版本规划 | 判断变更是否进入当前版本或后续版本 |
| 产品路线图 | 判断变更是否影响中长期方向 |
| PRD 生成 | 接受变更后需要更新 PRD |
| 验收标准 | 接受变更后可能需要更新验收标准 |

## 输出边界

需求变更评估不直接重写完整 PRD，不直接改开发排期，也不直接替团队做最终批准。

它应该输出：

- 变更摘要。
- 变更原因。
- 影响范围。
- 风险和依赖。
- 处理建议。
- 必须同步更新的文档。
- 决策人和待确认问题。

## 质量重点

- 不能只回答“可以改”或“不建议改”。
- 必须说明影响范围。
- 必须说明是否影响时间、资源、风险和下游协作。
- 必须保留待确认问题和决策责任。
- 必须给出可执行的处理建议。
