# 输入分析

## 任务类型

这是产品经理能力建设项目，不是真实业务策略判断项目。

本项目要建设的是一套可复用方法，让后续真实项目可以使用它生成产品策略判断结果。

## 能力定位

产品策略判断位于产品能力链路的上层，主要回答：

- 方向是否成立。
- 目标用户是谁。
- 核心价值是什么。
- 业务目标是否匹配。
- 是否具备当前推进条件。
- 哪些事情应该做，哪些事情应该暂缓。

## 与已有能力的关系

| 能力 | 关系 |
| --- | --- |
| 用户反馈整理 | 为策略判断提供用户问题和痛点来源 |
| 竞品分析 | 为策略判断提供市场变化、差异和机会 |
| 需求分析 | 把策略方向拆成具体需求前，需要先明确策略是否成立 |
| PRD 生成 | PRD 应承接已经成立的策略方向 |
| 优先级判断 | 策略判断决定方向，优先级判断决定同一方向下先后 |
| 版本规划 | 版本规划把策略和优先级落到阶段路线 |

## 输出边界

产品策略判断不直接输出完整 PRD，不直接拆功能，也不直接做版本排期。

它应该输出：

- 策略目标。
- 用户与场景。
- 机会判断。
- 价值判断。
- 约束与风险。
- 策略选择。
- 后续动作建议。

## 质量重点

- 不能只写口号。
- 不能脱离输入材料空泛判断。
- 需要保留不确定性。
- 需要说明为什么现在做或为什么暂缓。
- 输出必须能进入需求分析、优先级判断或版本规划。
