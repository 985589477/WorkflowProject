# 输入分析

## 输入是否充足

输入充足。

当前能力建设目标明确：需要抽象版本规划流程，而不是为某个具体产品直接排期。

## 版本规划要解决的问题

产品经理在有了功能清单和优先级之后，还需要决定各版本怎么分阶段交付。如果没有版本规划，容易出现：

- v1 范围过大。
- 后续版本目标不清楚。
- P0、P1、P2 和版本阶段混淆。
- 把所有功能都塞进当前版本。
- 缺少版本之间的依赖关系和演进逻辑。

## 设计原则

1. 先明确产品阶段目标。
2. 版本规划必须承接优先级判断。
3. 当前版本必须聚焦最小可用价值。
4. 后续版本应体现自然演进，而不是功能堆砌。
5. 明确每个版本做什么、不做什么。
6. 保留风险、依赖和待确认问题。

## 输出结构建议

版本规划应至少包含：

- 规划目标。
- 版本阶段。
- 每个版本的目标。
- 每个版本包含功能。
- 每个版本不包含内容。
- 依赖关系。
- 风险和待确认问题。
- 后续建议。
