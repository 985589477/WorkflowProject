# 输入分析

## 任务类型

这是产品经理能力建设项目，不是真实需求池运营项目。

本项目要建设的是一套可复用方法，让后续真实项目可以把多个来源的需求稳定整理成可管理的需求池。

## 能力定位

需求池管理位于产品经理长期管理能力层。

它主要回答：

- 需求从哪里来。
- 需求是什么类型。
- 需求当前处于什么状态。
- 需求是否需要补充分析。
- 需求是否进入优先级判断、PRD 或版本规划。
- 需求为什么暂缓、拒绝或归档。

## 与已有能力的关系

| 能力 | 关系 |
| --- | --- |
| 用户反馈整理 | 为需求池提供需求来源和痛点线索 |
| 需求分析 | 对需求池中的候选需求进行结构化分析 |
| 产品策略判断 | 判断需求是否符合产品方向 |
| 优先级判断 | 对需求池中的候选项排序 |
| PRD 生成 | 将确认推进的需求转化为 PRD |
| 版本规划 | 将确认推进的需求分配到版本阶段 |

## 输出边界

需求池管理不直接输出完整 PRD，不直接做功能细节设计，也不直接确定最终排期。

它应该输出：

- 需求池总览。
- 需求来源和分类。
- 需求状态。
- 优先级线索。
- 版本归属建议。
- 风险和待确认问题。
- 后续处理动作。

## 状态建议

需求池默认状态可以包括：

| 状态 | 含义 |
| --- | --- |
| 新进入 | 刚进入需求池，尚未整理 |
| 待澄清 | 信息不足，需要补充背景或确认 |
| 待分析 | 可以进入需求分析 |
| 待判断 | 需要策略判断或优先级判断 |
| 待 PRD | 已确认推进，需要进入 PRD |
| 待版本规划 | 已有 PRD 或功能范围，需要进入版本规划 |
| 暂缓 | 方向可能成立，但当前不做 |
| 拒绝 | 不符合目标或价值不足 |
| 已归档 | 已完成、失效或不再跟进 |

## 质量重点

- 需求必须可追溯来源。
- 状态必须清楚。
- 不能把需求池写成杂乱列表。
- 需要保留后续动作。
- 需要避免所有需求都默认推进。
