# 输入分析

## 输入是否充足

输入充足。

当前已有 PRD、功能说明、功能清单和范围边界，足以抽象出功能规划工作流。

## 功能规划能力要解决的问题

PRD 会描述产品要做什么，但真实推进时还需要将功能拆成清楚的模块、优先级和版本范围。

如果缺少功能规划，容易出现：

- 功能列表只有罗列，没有先后顺序。
- P0、P1、后续版本混在一起。
- 版本目标不清楚。
- 开发和设计无法判断当前阶段该优先做什么。
- 暂不做范围被反复拉回当前版本。

## 设计原则

1. 先明确版本目标，再拆功能。
2. 功能必须能追溯到产品目标、用户场景或 PRD。
3. 区分 P0、P1、P2 和暂不做。
4. 明确依赖关系和风险。
5. 不把后续版本内容混入当前版本。
6. 对不确定内容写入待确认问题。

## 输出结构建议

功能规划应至少包含：

- 版本目标。
- 功能模块。
- 功能优先级。
- 功能范围。
- 依赖关系。
- 暂不做范围。
- 风险和待确认问题。
