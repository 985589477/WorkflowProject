# 需求分析

## 背景

WorkflowProject 已经开始沉淀角色、流程、模板、案例、评分表和可视化索引。

随着内容增多，仅依赖目录结构会让用户难以判断“当前有什么、该用哪个、如何启动、用完后如何沉淀”。因此，用户提出希望建设一个 AI 提示词模板管理工具，用于保存、分类、复用和优化提示词模板。

## 核心问题

表层诉求是“做一个管理 AI 提示词模板的工具”。

底层问题是：当 AI 协作资产越来越多时，用户缺少一个低成本的管理入口，无法稳定完成以下动作：

- 找到合适模板。
- 理解模板适用场景。
- 基于模板启动一次项目。
- 记录模板使用效果。
- 把项目经验反向沉淀为更好的模板。

## 目标用户

第一阶段目标用户：

- WorkflowProject 当前维护者。
- 需要经常让 AI 生成文档、工作流、分析结果或项目输出的人。

潜在后续用户：

- 产品经理。
- 设计师。
- 开发者。
- 使用 AI 协作完成项目文档的人。

## 使用场景

### 场景 1：查找模板

用户想启动一个任务，但不知道该使用哪个模板。

需要支持按角色、能力、场景、输出类型查找模板。

### 场景 2：理解模板

用户找到模板后，需要快速知道：

- 这个模板解决什么问题。
- 输入需要准备什么。
- 输出会得到什么。
- 使用前需要注意什么。

### 场景 3：复用模板

用户选择模板后，希望直接得到一段可复制的启动话术，或者直接创建对应项目。

### 场景 4：优化模板

用户完成项目后，希望记录模板是否好用、哪里卡住、下一版该怎么改。

### 场景 5：沉淀经验

当某次项目验证成功后，用户希望把优秀输出、评分标准或使用经验沉淀到全局资产中。

## 产品目标

第一阶段目标：

- 建立一个模板资产总览。
- 让用户能按角色和使用场景找到模板。
- 让每个模板都有明确职责、输入要求、输出结果和使用示例。
- 支持记录模板使用效果和优化建议。
- 支持从真实项目反向沉淀模板经验。

可衡量成功标准：

- 用户能在 1 分钟内找到当前任务可用模板。
- 用户能看懂模板适用场景和启动方式。
- 每次真实项目结束后能形成可追踪的模板反馈。
- 新增模板后能同步进入索引或可视化视图。

## 范围边界

### 第一阶段要做

- 模板列表。
- 模板分类。
- 模板详情。
- 使用示例。
- 使用记录。
- 优化记录。
- 与当前项目索引或可视化面板联动。

### 第一阶段不做

- 多人权限。
- 在线账号系统。
- 商业化模板市场。
- 自动执行所有 AI 工作流。
- 复杂数据统计看板。
- 直接替代当前项目目录结构。

## 已知事实

- 当前项目已经存在全局模板目录。
- 当前项目已经存在工作流目录。
- 当前项目已经存在项目索引。
- 当前项目已经存在 React 可视化面板。
- 用户希望降低项目使用成本。
- 用户希望后续能稳定复用 AI 协作能力。

## AI 推断

- 这个工具不应该只是“提示词收藏夹”，更应该是 AI 协作资产入口。
- 模板、workflow、案例、评分表之间需要建立关联关系。
- 第一阶段最有价值的形态可能是当前 React dashboard 的一个模块，而不是单独新建复杂产品。
- 如果未来项目增多，模板资产需要有状态字段，例如 draft、validated、deprecated。

## 待确认问题

- 这个工具是否只管理提示词模板，还是也管理 workflow、案例、评分表和知识库。
- 是否优先集成到 `15-dashboard`。
- 是否需要支持一键创建项目。
- 是否需要记录每次模板被哪个项目使用。
- 是否需要给模板增加版本号和适用状态。
- 是否需要支持全文搜索。

## 是否可以进入 PRD

可以进入 PRD 初稿，但需要保留关键待确认问题。

建议下一步先生成轻量 PRD，范围聚焦在：

- 模板资产总览。
- 模板详情页。
- 使用示例。
- 使用记录。
- 优化记录。

暂不进入复杂权限、协作和自动执行能力。
