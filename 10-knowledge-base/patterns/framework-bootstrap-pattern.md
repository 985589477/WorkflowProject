# 框架启动模式

## 适用场景

当你需要从一个模糊想法开始，搭建一个可长期维护的 AI 工作流文档项目时，使用这个模式。

适用任务包括：

- AI 文档工作流框架。
- AI 开发协作规范。
- AI 设计协作流程。
- AI 内容生产系统。
- 多角色 AI 协作项目。

## 来源案例

```text
09-examples/cross-functional/workflowproject-framework-bootstrap/
```

## 核心模式

```text
先做系统和治理
-> 再做通用工作流
-> 再做标准
-> 再做 meta 模板
-> 再做项目模板
-> 再补低成本入口
-> 再跑一个真实样板项目
-> 最后沉淀案例和知识
```

## 推荐步骤

1. 明确项目愿景和非目标。
2. 区分全局资产和项目现场。
3. 建立系统规则。
4. 建立治理规则。
5. 建立通用工作流。
6. 建立质量标准。
7. 建立 meta 模板。
8. 建立项目模板。
9. 建立进度汇报规则。
10. 建立可视化导图。
11. 用当前框架本身跑一个样板项目。
12. 将样板项目沉淀为正式案例。
13. 从案例中提炼知识和模板。

## 成功标志

- 新用户知道先看哪里。
- 新项目可以用脚本创建。
- 每个项目有输入、分析、提示词、输出、评审、复盘。
- 执行过程能记录当前进度和调度角色。
- 好项目能沉淀为案例。
- 案例能继续提炼成知识和模板。

## 常见错误

- 一开始写太多角色模板，但没有真实任务验证。
- 只搭目录，不写治理规则。
- 只保存结果，不记录过程。
- 案例库混入未经评审的输出。
- README 承担过多细节，导致入口变重。

## 使用方式

新建类似框架时，可以先让 AI 参考本模式，再结合具体领域生成项目结构。

推荐提示：

```text
请参考 10-knowledge-base/patterns/framework-bootstrap-pattern.md，
帮我为一个新的 AI 工作流项目设计系统层、治理层、工作流层、标准层、模板层、项目模板和案例沉淀流程。
```
