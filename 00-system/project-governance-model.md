# 项目治理模型

## 项目重新定位

WorkflowProject 的首要目标不是生产尽可能细的 AI 角色提示词，而是为长期 AI 协作开发项目提供一套可检查、可补齐、可持续维护的工程治理约束。

角色能力、工作流、模板和评分表都是可选工具，项目架构、模块边界、设计规范、任务列表和模块文档才是实际开发时的核心事实来源。

一句话定位：

```text
WorkflowProject = 帮助 AI 在真实项目中先建立治理基础，再受约束地理解、规划、实现和验证。
```

## 核心目标

项目治理需要保证：

- AI 开始开发前知道项目是什么、怎么运行、哪些规则优先。
- 新项目或新模块开始前，先通过问询确认目标平台、主要语言、框架、运行方式和测试方案。
- 新需求进入后，能够识别影响的模块、接口、数据和设计范围。
- 模块有清晰职责、输入、输出、依赖和禁止承担的职责。
- 设计规范能够约束颜色、字体、组件、状态、布局和设备适配。
- 功能能够拆成可逐条执行、逐条验证的任务列表。
- 代码、模块文档、架构文档和测试结果能够同步演进。
- 缺少治理材料时，AI 先与用户协作补齐，而不是自行假设后直接写代码。

## 新的主次关系

```text
项目治理约束
-> 项目事实文档
-> 团队总调度
-> 可选角色能力
-> 阶段工作流
-> 任务执行和验证
```

角色不再是固定的主流程。角色只有在任务确实需要专业判断时才参与：

- 产品经理：需求、目标、范围和验收标准不清时参与。
- UI 设计师：页面、组件、交互、视觉或多端适配不清时参与。
- 开发工程师：架构、模块、实现、配置和代码变更需要判断时参与。
- 测试工程师：测试范围、质量风险、回归或发布验收需要判断时参与。

总调度可以调用角色，也可以只使用开发治理流程。不得为了形式完整而强制所有角色参与。

## 三类事实

所有 AI 输出都要区分：

```text
已确认事实：来自项目文件、代码、用户明确说明或验证结果。
AI 推断：根据目录、代码模式或上下文推导出的暂时判断。
待用户确认：存在多种合理方案、风险较高或影响范围尚未确定的内容。
```

AI 不得把推断直接写成项目规范，也不得把待确认方案直接当成架构决策。

## 最小治理集

长期开发项目至少需要具备：

```text
项目规则入口
项目说明
架构概览
模块地图与模块边界
设计规范或明确的无设计规范说明
开发任务列表
验证规则和验证结果
项目记忆摘要
```

项目可以根据复杂度裁剪文件，但不能跳过对应职责。轻量项目可以合并文档，中大型项目应拆分文档。

## 治理门禁

进入代码实现前，默认检查：

1. 项目入口、技术栈、启动和验证方式。
2. 新项目或新模块的技术方案是否已经通过问询确认。
3. 项目规则和已有规范。
4. 架构、模块边界和本次影响范围。
5. 设计规范、组件状态和设备适配要求。
6. 数据、接口、状态、权限和安全风险。
7. 功能整体规划和开发任务列表。
8. 用户是否确认进入实现。

### 技术方案问询门禁

以下情况必须先问询，不能静默选择：

- 没有现有项目，需要从零搭建。
- 现有项目没有明确技术栈，或代码和配置出现冲突。
- 新模块需要引入不同语言、框架、运行时或独立构建方式。
- 用户只描述了功能目标，没有说明目标平台或运行环境。

最少询问：

```text
1. 目标平台是什么：网页、移动端、桌面端、服务端，还是其他？
2. 主要使用什么语言？
3. 是否指定框架及版本？如果没有，我可以提供 2-3 个方案供你选择。
4. 运行、构建和部署环境是什么？
5. 测试希望使用什么方式或工具？
6. 新模块是沿用当前项目技术栈，还是允许使用独立技术栈？
```

已有项目技术栈明确时，AI 仍需先报告识别结果，并询问“是否沿用当前技术栈”；只有用户确认或项目规则已经明确授权时，才进入实现。

缺少材料时，AI 应输出缺口、影响和补齐选项，并与用户交互构建，不应为了继续执行而静默补全关键事实。

## 防止过度约束

- 规则约束目标、边界、风险和验收，不规定每一行代码怎么写。
- 角色提供专业视角，不替代模型对具体项目的判断。
- 工作流定义检查顺序，不强迫所有任务经过全部阶段。
- 模板规定最小信息集合，不限制输出内容的专业深度。
- 小任务可以轻量执行，但必须说明跳过了哪些检查以及原因。
- 复杂任务必须留下可审计的规划、任务和验证证据。

## 评估标准

本项目后续判断是否有效，不看角色文档数量，而看 AI 能否在真实项目中做到：

- 先发现项目治理缺口。
- 先询问关键不确定项。
- 先产出架构、模块和任务计划。
- 按任务列表逐条实现。
- 每条任务完成后进行验证。
- 在代码、文档和测试之间保持一致。
- 遇到冲突时停下来反馈，而不是自行扩大范围。
