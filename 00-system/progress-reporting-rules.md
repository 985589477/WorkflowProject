# 进度汇报规则

## 目的

在执行项目时，让用户随时知道：

- 当前进行到哪一步。
- 调度了哪个 AI 角色。
- 使用了哪个工作流或模板。
- 当前产出了什么。
- 下一步要做什么。

## 适用范围

适用于所有 `12-projects/` 下的具体项目。

## 对话中的进度汇报

执行项目时，AI 应在关键节点输出简短进度：

```text
当前进度：正在分析输入材料。
调度角色：通用文档分析助手。
使用流程：04-workflows/common/input-analysis-workflow.md。
下一步：整理结构化输入并保存到 02-analysis/。
```

## 项目内进度记录

每个项目建议维护：

```text
00-progress/progress-log.md
```

用于记录关键动作。

## 推荐记录格式

```md
## YYYY-MM-DD HH:mm

- 当前阶段：
- 调度角色：
- 使用工作流：
- 使用模板：
- 输入位置：
- 输出位置：
- 当前结果：
- 下一步：
```

## 必须记录的节点

- 创建项目。
- 完成输入分析。
- 生成或选择模板。
- 生成正式提示词。
- 执行 AI 输出。
- 完成输出评审。
- 完成资产提升判断。
- 完成项目复盘。

## 注意事项

- 进度汇报要短，不要替代正式文档。
- 调度角色必须写清楚，避免不知道是谁在执行。
- 如果没有使用具体模板，写“未使用具体模板”。
- 如果下一步不确定，写“待确认”。
