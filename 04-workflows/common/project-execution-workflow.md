# 项目执行总控工作流

## 目的

把一次具体任务从创建项目到最终沉淀串成完整流程。

## 适用场景

适用于所有 `12-projects/` 下的新任务。

## 输入要求

- 用户原始描述、模糊想法或原始材料。
- 项目角色或任务类型。
- 期望输出。

## 执行步骤

1. 创建项目目录。
2. 在 `00-progress/progress-log.md` 记录项目启动。
3. 判断用户是否已经有标准输入。
4. 如果只有模糊想法，先使用想法转输入工作流，生成 `01-inputs/original-requirement.md`。
5. 如果已有原始材料，直接放入 `01-inputs/`。
6. 使用输入分析工作流，输出到 `02-analysis/`。
7. 判断是否已有合适模板。
8. 如果没有模板，使用模板生成器生成初版模板。
9. 使用模板和输入材料生成正式提示词，保存到 `03-prompts/`。
10. 执行 AI 任务，输出保存到 `04-outputs/`。
11. 使用输出评审器评审结果，保存到 `05-review/`。
12. 使用资产提升工作流判断是否沉淀为全局资产。
13. 将经验和提升记录保存到 `06-lessons/`。
14. 刷新可视化视图。

## 进度汇报要求

每完成一个关键阶段，都要在对话中简短说明：

```text
当前进度：
调度角色：
使用工作流：
使用模板：
下一步：
```

同时将关键节点写入：

```text
00-progress/progress-log.md
```

重要方向选择写入：

```text
00-progress/decision-log.md
00-progress/next-actions.md
```

## 输出结果

一个完整项目至少包含：

```text
00-progress/progress-log.md
01-inputs/
02-analysis/
03-prompts/
04-outputs/
05-review/
06-lessons/
```

## 质量检查

- 是否有原始输入。
- 如果用户只有模糊想法，是否先生成了标准输入。
- 是否有输入分析。
- 是否有正式提示词。
- 是否有 AI 输出。
- 是否有输出评审。
- 是否有复盘记录。
- 是否记录了调度角色和执行进度。
- 是否记录了重要决策和下一步选项。
- 是否完成资产提升判断。
