# 资产提升工作流

## 目的

判断一个项目产物是否应该从 `12-projects/` 提升到全局资产目录。

## 适用场景

当一个项目完成后，需要决定哪些内容值得长期复用时使用。

## 输入要求

至少准备：

- 项目输入材料
- 项目正式提示词
- AI 输出
- 输出评审
- 项目复盘

## 执行步骤

1. 检查项目是否已经完成评审。
2. 判断产物类型。
3. 判断是否具备复用价值。
4. 决定提升目标目录。
5. 复制或整理内容到全局目录。
6. 在项目 `06-lessons/promotion-notes.md` 中记录提升结果。

## 提升规则

### 提升为模板

如果某个提示词结构可以反复用于类似任务，提升到：

```text
06-templates/{角色}/
```

提升前必须符合：

```text
05-standards/template-standard.md
```

### 提升为优秀案例

如果某次任务链路完整、输出质量高、后续可参考，提升到：

```text
09-examples/{角色}/
```

提升前必须符合：

```text
05-standards/example-standard.md
```

### 提升为知识

如果从项目中总结出跨任务规律，提升到：

```text
10-knowledge-base/
```

例如：

- 成功模式
- 反模式
- 最佳实践
- 可复用片段
- 经验复盘

### 提升为评估方法

如果项目中形成了稳定评分表或测试方法，提升到：

```text
11-evaluations/
```

### 仅归档

如果项目不再使用，但需要保留记录，移动到：

```text
99-archive/
```

## 输出结果

输出一份提升记录，建议保存为：

```text
12-projects/{角色}/{项目名}/06-lessons/promotion-notes.md
```

## 质量检查

- 是否说明提升了哪些内容。
- 是否说明没有提升哪些内容。
- 是否说明提升原因。
- 是否放入正确全局目录。
- 是否避免把单次业务细节误放入通用模板。
