# 0002 以项目治理为核心重新定位

状态: accepted

## 背景

项目已经形成产品经理、UI 设计师、开发工程师、测试工程师和跨角色团队能力包。继续无限细化角色，会增加使用成本，并可能让 AI 机械执行角色提示词，反而削弱它对真实项目的判断能力。

用户真正需要的是长期项目治理：在 AI 写代码前检查项目架构、模块边界、设计规范、任务列表和模块文档；缺失时与用户协作补齐；存在时以真实项目文档为事实来源完成开发。

## 决策

WorkflowProject 重新定位为“面向 AI 协作开发的项目治理约束框架”。

核心主轴调整为：

```text
项目治理检查
-> 项目事实补齐
-> 整体规划
-> 任务拆解
-> 逐条执行
-> 验证和文档同步
```

产品、UI、开发和测试能力保留为可按需调用的专业能力，不再默认要求所有项目或任务完整经过所有角色。

新增通用主流程：

```text
04-workflows/common/project-governance-workflow.md
```

新增治理标准和检查模板：

```text
05-standards/project-governance-standard.md
06-templates/common/project-governance-checklist-template.md
```

## 影响

- 真实项目的架构、模块、设计和任务文档优先于通用角色包建议。
- 角色包负责专业判断，不负责替代真实项目事实。
- 轻量任务可以跳过不必要阶段，但必须说明原因。
- 中大型任务必须形成可检查的规划、任务和验证证据。
- 后续新增能力优先判断是否属于项目治理共性，避免重复新增角色。
