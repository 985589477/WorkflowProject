# 输出评分表

这里存放可复用的输出评分表，用于判断某类 AI 输出是否合格、是否可以进入下一阶段。

## 当前评分表

- `project-completion-scorecard.md`：评估项目是否完成。
- `understanding-check-scorecard.md`：评估 AI 是否理解用户意图。
- `capability-export-scorecard.md`：评估导出的角色能力包或专项能力包是否完整、清晰、可独立使用。
- `requirement-analysis-scorecard.md`：评估产品经理需求分析结果是否可以进入 PRD。
- `prd-scorecard.md`：评估产品经理 PRD 结果是否可以进入 UI 设计、开发拆解或下一阶段。
- `acceptance-criteria-scorecard.md`：评估验收标准是否可以进入测试用例、开发验收或上线验收。
- `feature-planning-scorecard.md`：评估功能规划是否可以进入 UI 设计、开发拆解或版本规划。
- `user-story-scorecard.md`：评估用户故事是否可以进入验收标准、UI 设计或开发拆解。
- `user-feedback-scorecard.md`：评估用户反馈整理是否可以进入需求分析、需求池或优先级判断。
- `competitor-analysis-scorecard.md`：评估竞品分析是否可以进入需求分析、产品策略或功能规划。
- `priority-decision-scorecard.md`：评估优先级判断是否可以进入版本规划、功能规划或开发排期。
- `version-planning-scorecard.md`：评估版本规划是否可以进入路线图、开发排期或发布计划。
- `product-strategy-scorecard.md`：评估产品策略判断是否可以进入需求分析、优先级判断、版本规划或路线图。
- `requirement-pool-scorecard.md`：评估需求池是否可以支持需求分析、策略判断、优先级判断、PRD 或版本规划。
- `product-roadmap-scorecard.md`：评估产品路线图是否可以进入 PRD、版本规划、开发排期或团队沟通。
- `requirement-change-evaluation-scorecard.md`：评估需求变更判断是否可以支持团队做变更决策。
- `version-retrospective-scorecard.md`：评估版本复盘是否可以支持下一轮需求池、路线图、版本规划或流程改进。

## 使用方式

1. 先确定当前输出类型。
2. 选择对应评分表。
3. 按评分维度逐项打分。
4. 根据总分判断是否继续推进、补充输入或重新生成。
