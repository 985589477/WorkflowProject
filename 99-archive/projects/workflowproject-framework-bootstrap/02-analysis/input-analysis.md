# 输入分析

## 任务类型

这是一个跨角色的 AI 工作流文档系统建设任务，不属于单一产品、开发或设计任务。

## 核心问题

用户需要解决的不是“写一个提示词”，而是建立一套能持续生产、评审、沉淀提示词资产的项目框架。

## 稳定结构

该类任务具有稳定结构：

```text
需求澄清
-> 框架设计
-> 目录规划
-> 治理规范
-> 标准体系
-> 模板体系
-> 项目执行流程
-> 可视化导图
-> 自检和复盘
```

## 可变输入

后续类似项目中会变化的内容：

- 支持的角色类型。
- 工作流复杂度。
- 是否需要图形化导图。
- 是否需要真实项目样板。
- 是否需要版本管理和质量门禁。

## 选择的方案

采用“全局资产 + 项目现场”的双层结构：

- `00-system` 到 `11-evaluations` 存放全局可复用资产。
- `12-projects` 存放每次真实任务的项目现场。
- `99-archive` 存放历史和废弃内容。

## 关键决策

将 WorkflowProject 本身作为第一个 `mixed` 类型项目，用来验证框架逻辑。
