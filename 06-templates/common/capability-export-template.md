# 能力导出模板

状态: draft
版本: v1
角色: common

## 适用场景

当需要把 WorkflowProject 中某个角色或某组能力导出成独立能力包时使用。

本模板用于生成：

```text
14-exports/{kit-name}/
```

## 输入变量

```text
{导出对象}
{导出目标目录}
{使用对象}
{使用场景}
{包含范围}
{排除范围}
{来源文件}
{导出时间}
{是否包含示例}
{是否包含评分表}
{维护方式}
```

## 生成要求

1. 明确导出包边界。
2. 输出导出资产清单。
3. 生成统一格式的能力包入口 `START-HERE.md`。
4. 生成独立 README。
5. 生成使用指南。
6. 生成来源清单 `manifest.md`，并记录导出时间。
7. 不使用版本号，后续维护只更新导出时间。
8. 不要把一次性项目过程材料直接塞进导出包。
9. 如果缺少必要资产，写入风险与待补充内容。

## START-HERE 统一格式

所有导出包都必须包含 `START-HERE.md`。

具体格式以以下标准文件为准：

```text
05-standards/exported-kit-start-here-standard.md
```

生成时使用以下结构：

````md
# 从这里开始

导出对象：{导出对象}
导出时间：{导出时间}

## 这个包能做什么

{用 3-7 条说明能力包可处理的任务}

## 什么时候使用这个包

当用户输入包含以下意图时，优先使用本能力包：

- {触发场景 1}
- {触发场景 2}
- {触发场景 3}

## 一句话启动

```text
请只参考 {kit-name}/ 下的文件工作。请先阅读 {kit-name}/README.md、{kit-name}/usage-guide.md 和 {kit-name}/{主入口 workflow 路径}。我的任务是：{写下你的任务}。请先判断任务类型，再说明会使用哪个 workflow、template 和 scorecard，然后继续产出结果。
```

## 更短版本

```text
请使用 {kit-name} 处理我的任务：{写下你的任务}
```

## 外部自动读取配置

如果希望用户不输入“请使用 {kit-name}”，可以在新项目根目录放置默认读取文件，例如：

```text
AI-WORKFLOW-RULES.md
```

并写入：

```text
你是当前项目的 AI 工作流调度器。

当用户输入任务时，请先判断是否属于 {导出对象} 能力范围。

如果属于，请自动调用 {kit-name}，并先阅读：
1. {kit-name}/START-HERE.md
2. {kit-name}/README.md
3. {kit-name}/usage-guide.md
4. {kit-name}/{主入口 workflow 路径}

执行前请先说明：
- 你判断这是哪一类任务。
- 你将使用哪个 workflow。
- 你将参考哪个 template。
- 你将使用哪个 scorecard 检查结果。

如果不属于本能力包范围，请不要强行调用。
如果无法判断任务类型，请先向用户确认。
```

## 执行顺序

1. 先判断任务类型。
2. 再选择对应 workflow。
3. 再选择对应 template。
4. 产出结果后使用对应 scorecard 检查。
5. 如果信息不足，先列出待确认问题。

## 外部项目输出目录策略

当本能力包在其他项目中使用，并且用户要求把结果保存为文件时，必须先判断当前项目是否已有统一文档目录。

优先级如下：

1. 如果用户明确指定输出目录，使用用户指定目录。
2. 如果项目已有统一文档目录，优先使用该目录，例如 `docs/`、`documents/`、`产品文档/`、`需求文档/`。
3. 如果项目已有明确的领域文档目录，优先使用该目录，例如 `docs/product/`、`docs/prd/`、`product-docs/`。
4. 如果没有任何合适目录，再在项目根目录创建 `docs/`。

不要在外部项目中默认创建或使用 WorkflowProject 内部目录，例如：

```text
{目标文档目录}/
12-projects/
```

如果只是对话中直接输出结果，不需要创建文件。

## 输出确认格式

每次执行前，先输出：

```text
任务判断：{任务类型}
调用能力包：{kit-name}
使用工作流：{workflow}
使用模板：{template}
检查标准：{scorecard}
保存位置：{对话直接输出 / 用户指定目录 / 已有文档目录 / docs/}
```

## 使用原则

- 不确定做什么时，先走总入口。
- 已经明确任务时，直接指定对应工作流。
- 生成结果后，用对应评分表检查。
- 不需要理解原 WorkflowProject。
````
